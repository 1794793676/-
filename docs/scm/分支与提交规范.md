## 二、提交规范

## 三、Code Review 与合并

- PR #1（US01）、PR #2（US02）、PR #3（US03）均由至少 1 名其他成员审查；合并后删除 feature 分支。
- 未在 `main` 直接提交；未使用 `git push --force`；合并一律使用 `--no-ff` 保留分支信息。
- PR 描述包含：关联任务/变更编号、改动与未改动范围、测试命令与结果、风险与回滚方式。
- 评审清单与逐条结论见 `docs/scm/评审记录.md`。

## 四、禁止事项

1. 禁止直接向 `main` 推送，禁止 `git push --force` 覆盖他人提交。
2. 禁止改写已共享历史（`rebase`、`amend` 只用于未推送的本地提交）。
3. 禁止把密钥、真实学籍与联系方式、申请材料原件提交入库（`.gitignore` 已排除 `runtime/`、`.env`、`.test-tmp/`）。
4. 禁止在未通过评审与测试时合并，禁止把失败用例写成通过。

## 五、标签与版本

- 语义化版本 `MAJOR.MINOR.PATCH`：不兼容 API 变更升 MAJOR；向下兼容功能新增升 MINOR；向下兼容缺陷修复升 PATCH。
- 发布时由团队确认版本号，SM 打**注释标签**并写清发布范围：

  ```sh
  git tag -a v1.0.0 -m "Sprint 1 发布：US01–US03 通知、申请与辅导员初审"
  git push origin v1.0.0
  ```

- 标签只指向已通过全量测试与 PO 验收的 `main` 提交，与 Release Notes 一一对应；已发布标签不得移动或覆盖。
