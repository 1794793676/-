## 二、版本号规则

采用语义化版本 `MAJOR.MINOR.PATCH`：

- `v1.0.0` 表示首个可运行 Sprint 增量（US01–US03，26SP，通过 DoD 与 PO 验收）；
- 后续不兼容 API 变更升 MAJOR，向下兼容的功能新增升 MINOR，问题修正升 PATCH；
- 标签必须指向通过全量测试与 PO 验收的 `main` 提交，并在本表回填基线提交号。

## 三、存储与控制要求

1. 所有源代码、测试、文档与脚本纳入 Git；`runtime/`、`.test-tmp/`、`__pycache__/`、`.env` 由 `.gitignore` 排除。
2. 配置项变更先提 Issue/任务卡，经变更控制流程审批后实施，未经审批不合入 `main`。
3. 可执行制品发布时上传 GitHub Release，并登记文件名与校验和。
4. 本清单自身是受控配置项（CI-09），修改需在提交信息中说明理由。
