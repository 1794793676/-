# 合并冲突演练记录（模拟记录）

> **教学模拟说明**：本记录为实验三教学模拟稿，用于演示"人为制造同行冲突 → 人工消解 → 合并"的完整过程，**不冒充真实操作留痕**。实际演练时把命令输出与截图存入 `docs/scm/证据/冲突演练/`。

## 一、演练设计

| 项目 | 内容 |
| --- | --- |
| 目的 | 复现同行冲突，掌握手工消解，明确禁止 `git push --force` |
| 参与人 A | Dev 1 陈志成（`feature/a`） |
| 参与人 B | Dev 2 涂先诚（`feature/b`） |
| 冲突文件 | `README.md` 第一行（项目标题行） |
| 观察与记录 | SM 何昊锵 |
| 时间盒 | 演练 15 分钟，冲突消解与复测 10 分钟 |

## 二、演练步骤

1. 两人各自从最新 `main` 建分支：

   ```sh
   git checkout main && git pull origin main
   git checkout -b feature/a
   ```

2. A 修改 `README.md` 第一行并提交、推送：

   ```sh
   git commit -am "docs: 更新项目标题（成员A）"
   git push -u origin feature/a
   ```

3. B 同样从最新 `main` 建 `feature/b`，把同一行改成不同内容并提交、推送。

4. 先把 `feature/a` 合入 `main`，再合并 `feature/b` 时产生冲突：

   ```sh
   git checkout main && git pull origin main
   git merge feature/b
   ```

   冲突标记：

   ```text
   <<<<<<< HEAD
   main 分支上的内容
   =======
   feature/b 分支上的内容
   >>>>>>> feature/b
   ```

5. B 手动编辑文件，选择保留的内容（或合并两者），删除全部冲突标记，然后提交合并结果：

   ```sh
   git add README.md
   git commit -m "merge: 解决README合并冲突"
   git push origin main
   ```

## 三、演练结果

| 项目 | 记录 |
| --- | --- |
| 冲突文件与位置 | `README.md` 第 1 行 |
| 冲突块数 | 1 处 |
| 消解方式 | 保留合并后的统一表述，删除三行冲突标记 |
| 消解提交信息 | `merge: 解决README合并冲突` |
| 是否使用 `git push --force` | **否** |
| 合并后状态 | `main` 可运行，全量测试通过，README 标题为合并后内容 |
| 结论 | 冲突已手动解决；未强推；合并后 main 保持可运行 |

## 四、经验与禁止事项

1. 冲突必须人工解决，禁止整文件覆盖或用强推掩盖。
2. 合并提交使用 `merge:` 前缀，并在正文写明解决的文件与取舍理由。
3. 消解后必须重新运行受影响测试与全量测试，再由非提交者评审后合入。
4. 已推送的共享历史不得改写；`git push --force` 为团队协作中的高危操作，本轮明令禁止。
