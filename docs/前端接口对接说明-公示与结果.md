## 一、这份文档能解决什么

前端要接"学生处发公示"和"学生查最终结果"，需要知道四件事：

1. 用哪个账号能调哪些接口（角色边界）；
2. 每个接口的请求、响应字段长什么样；
3. 失败时会拿到哪个 `error.code`，该提示什么；
4. 公示名单里**只能出现哪些字段**（脱敏白名单，不能多也不能少）。

本文按这个顺序写。所有示例 JSON 都是本机实测输出，可直接对照。

## 四、状态机（本轮补上后半段）

```
待辅导员审核 --approve--> 待学院复核 --approve--> 待公示 --发布公示--> 公示中 --整批确认--> 已获批 / 未获批
      |                        |                                        |
    reject                   reject                              公示期未结束 → 拒绝确认
      ↓                        ↓
    已驳回                   已驳回（终态，不进公示）
```

关键约定：

- **发布是整批的**：一次发布把"同一项目 + 同一批次"里所有 `待公示` 申请一起变成 `公示中`，不存在只公示一部分。
- **批次里还有没审完的，整批不让发**（返回 `BATCH_INCOMPLETE`），避免同一批次出现"一半在公示、一半还在审"。
- **最终结果也是整批的**：确认时必须覆盖该批次全部申请，少一条就报 `BATCH_INCOMPLETE`，禁止部分提交。
- **公示期结束 + 线下异议已处理**，两个条件同时满足才能确认最终结果。

## 五、接口总览

所有接口都要求先登录（`sid` Cookie），非 GET 请求必须带 `X-CSRF-Token`（取自 `POST /api/login` 或 `GET /api/session` 的 `csrf_token`）。统一响应格式仍是 `{"ok":true,"data":...}` / `{"ok":false,"error":{...}}`。

| 方法 | 路径 | 允许角色 | 用途 |
| --- | --- | --- | --- |
| GET | `/api/publications/pending` | 学生处 | 可发布的"项目 + 批次"清单 |
| POST | `/api/publications` | 学生处 | 整批发布公示 |
| GET | `/api/publications` | 任意登录用户 | 公示批次列表（只有元数据） |
| GET | `/api/publications/{id}` | 任意登录用户 | 单个批次详情 + 脱敏名单 |
| GET | `/api/publications/{id}/items` | 学生处 | 确认用的待办名单（多一个申请编号） |
| POST | `/api/publications/{id}/finalize` | 学生处 | 整批确认最终结果 |
| GET | `/api/publications/{id}/results` | 学生处 | 该批次结果明细（含未脱敏原因） |
| GET | `/api/results/me` | 学生 | 本人全部申请进度与结果 |
| GET | `/api/applications/{id}/result` | 学生（仅本人） | 单个申请的进度与结果 |

补充：`GET /api/applications` 现在对 `student_affairs` 返回 `403`。学生处只通过公示接口看脱敏数据，拿不到申请明细和附件，这是有意的隔离。

## 六、逐接口说明

### 6.1 GET /api/publications/pending

学生处挑批次用。只列出"还有 `待公示` 记录"的项目批次。

响应 `200`：

```json
{"ok":true,"data":[
  {"project_id":"open","project_name":"2026秋季学业奖学金","batch":"2026秋季第一批","pending_count":3}
]}
```

没有待公示数据时返回 `[]`。

### 6.2 POST /api/publications

整批发布。成功返回 `201`。

请求：

```json
{
  "project_id": "open",
  "batch": "2026秋季第一批",
  "start_at": "2026-11-14T00:00:00+08:00",
  "end_at": "2026-11-20T00:00:00+08:00",
  "proposed_level": "一等助学金"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `project_id` | string | 是 | 项目 id，取自 `/api/projects` |
| `batch` | string | 是 | 批次，取自 `/api/publications/pending` 或申请记录 |
| `start_at` | string | 是 | ISO 8601 公示开始时间 |
| `end_at` | string | 是 | ISO 8601 公示结束时间，必须晚于 `start_at` |
| `proposed_level` | string | 是 | 拟获等级/名称，≤100 字，会原样出现在公示名单里 |

响应 `201`：

```json
{"ok":true,"data":{
  "id":"PUB-61D7F965FC444C60","project_id":"open","project_name":"2026秋季学业奖学金",
  "batch":"2026秋季第一批","proposed_level":"一等助学金",
  "start_at":"2026-11-14T00:00:00+08:00","end_at":"2026-11-20T00:00:00+08:00",
  "published_at":"2026-11-15T20:30:17+09:00","status":"公示中",
  "objection_handled":false,"confirmed_by":null,"confirmed_at":null,
  "items":[{"masked_name":"陈**","masked_student_id":"s***2","college":"计算机学院",
            "project_name":"2026秋季学业奖学金","proposed_level":"一等助学金"}],
  "item_count":3
}}
```

**时区务必注意**：`start_at` / `end_at` 必须带时区偏移（`+08:00` 或 `Z`）。如果传 `datetime-local` 的裸值（如 `2026-11-20T00:00`），后端会当作 **UTC**，公示结束时间会比预期晚 8 小时，学生处就会一直等到"公示期未结束"。

前端最稳的写法：

```js
const start_at = new Date(startInput.value).toISOString();   // 本地时间 → UTC ISO
const end_at   = new Date(endInput.value).toISOString();
```

### 6.3 GET /api/publications

任意登录用户可读，返回批次元数据列表（**不含名单**，名单要按 id 单独取，避免列表页拖大数据）。

```json
{"ok":true,"data":[
  {"id":"PUB-61D7F965FC444C60","project_id":"open","project_name":"2026秋季学业奖学金",
   "batch":"2026秋季第一批","proposed_level":"一等助学金",
   "start_at":"2026-11-14T00:00:00+08:00","end_at":"2026-11-20T00:00:00+08:00",
   "published_at":"2026-11-15T20:30:17+09:00","status":"公示中",
   "objection_handled":false,"confirmed_by":null,"confirmed_at":null}
]}
```

按 `published_at` 倒序。

### 6.4 GET /api/publications/{id}

批次详情 + 脱敏名单。

```json
{"ok":true,"data":{
  "id":"PUB-61D7F965FC444C60","status":"公示中","item_count":3,
  "items":[
    {"masked_name":"陈**","masked_student_id":"s***2","college":"计算机学院",
     "project_name":"2026秋季学业奖学金","proposed_level":"一等助学金"},
    {"masked_name":"林**","masked_student_id":"s***1","college":"计算机学院",
     "project_name":"2026秋季学业奖学金","proposed_level":"一等助学金"},
    {"masked_name":"王**","masked_student_id":"s***3","college":"文学院",
     "project_name":"2026秋季学业奖学金","proposed_level":"一等助学金"}
  ]
}}
```

元数据字段同 6.3，另加 `items`、`item_count`。

### 6.5 POST /api/publications/{id}/finalize

整批确认最终结果。成功返回 `200`，`status` 变 `已确认`。

请求：

```json
{
  "objection_handled": true,
  "decisions": {
    "APP-E3A72A20DF8443E4": {"decision":"approve"},
    "APP-9C1B77E0F2A34D51": {"decision":"reject","reason":"材料不足以证明家庭经济困难"}
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `objection_handled` | boolean | 是 | 必须显式为 `true`，代表线下异议已处理完 |
| `decisions` | object | 是 | key 是申请 id，value 是 `{decision, reason}` |
| `decisions.*.decision` | string | 是 | `approve` → 已获批；`reject` → 未获批 |
| `decisions.*.reason` | string | 驳回必填 | 非空，≤2000 字；通过时可为空 |

**必须覆盖整批**：`decisions` 的 key 集合要和该批次 `items` 里的申请 id 完全一致，多一个少一个都报 `BATCH_INCOMPLETE`。

响应 `200`：结构同 6.2，`status` 为 `已确认`，`objection_handled` 为 `true`，`confirmed_by`/`confirmed_at` 有值。

### 6.6 GET /api/publications/{id}/results

仅学生处。返回该批次每条申请的最终决定，含**未脱敏**的原因，用于线下归档核对。

```json
{"ok":true,"data":[
  {"application_id":"APP-9C1B77E0F2A34D51","decision":"reject",
   "reason":"材料不足以证明家庭经济困难","confirmed_by":"office1",
   "confirmed_at":"2026-11-21T10:00:00+08:00","status":"未获批"}
]}
```

### 6.7 GET /api/results/me

仅学生。返回本人所有申请（含还在审的），前端"我的申请"页可直接用这一个接口取代轮询。

```json
{"ok":true,"data":[
  {"application_id":"APP-E3A72A20DF8443E4","project_name":"2026秋季学业奖学金",
   "batch":"2026秋季第一批","status":"已获批","submitted_at":"2026-11-15T20:30:17+09:00",
   "final_reason":"","confirmed_at":"2026-11-21T10:00:00+08:00",
   "publication_id":"PUB-61D7F965FC444C60",
   "start_at":"2026-11-14T00:00:00+08:00","end_at":"2026-11-20T00:00:00+08:00"}
]}
```

- 还没形成最终结果时：`final_reason` 为 `""`，`confirmed_at` / `publication_id` 为 `null`。
- `status` 可能是 `待辅导员审核` / `待学院复核` / `待公示` / `公示中` / `已获批` / `未获批` / `已驳回`，前端按它渲染进度。

### 6.8 GET /api/applications/{id}/result

仅本人。返回单条，结构同 6.7 的数组元素。查别人的申请返回 `403 FORBIDDEN`，不存在返回 `404 NOT_FOUND`。

### 6.9 GET /api/publications/{id}/items

仅学生处。确认最终结果时 `decisions` 的 key 必须是申请编号，而公开名单按白名单不含编号，所以单独给一个学生处专用接口：**白名单 5 项 + `application_id`**，仍不含明文姓名、学号、电话、附件。

```json
{"ok":true,"data":[
  {"application_id":"APP-9C1B77E0F2A34D51","masked_name":"陈**","masked_student_id":"s***2",
   "college":"计算机学院","project_name":"2026秋季学业奖学金","proposed_level":"一等助学金"}
]}
```

前端确认表单就用它渲染：`application_id` 放进 `data-decision` / `data-reason`，其余字段直接显示。学生调这个接口返回 `403`。

## 七、脱敏白名单（重要）

公示名单是公开可见的，所以后端采用**白名单投影**：先从库里查出内部字段，再按固定字段名逐个取值组装，任何新增字段都进不了响应。

名单项**只有这 5 个字段**：

| 字段 | 示例 | 脱敏规则 |
| --- | --- | --- |
| `masked_name` | `林**` | 去掉"（演示）"等括注，只留姓氏首字 + `**` |
| `masked_student_id` | `s***1` | 首字符 + `***` + 末字符 |
| `college` | `计算机学院` | 原样 |
| `project_name` | `2026秋季学业奖学金` | 原样 |
| `proposed_level` | `一等助学金` | 原样（发布时填的） |

**不会返回**：学号原文、姓名全称、手机号、申请理由、任何附件、`rejection_reason`、审核意见、`student_id`、`reviewer_id`。

前端渲染时请直接使用这 5 个字段，不要试图从别处拼真实姓名；如果确实需要显示"本人是否在名单里"，用 `GET /api/results/me` 判断，不要靠名字匹配。

## 八、错误码表

沿用全局错误处理，`error` 对象固定含 `code` / `message` / `details` / `current_status`。

| HTTP | code | 触发场景 | 前端建议提示 |
| --- | --- | --- | --- |
| 400 | `INVALID_INPUT` | 必填字段缺失或不是非空字符串；`decisions` 不是对象/为空 | 检查表单必填项 |
| 400 | `INVALID_WINDOW` | 时间格式不是 ISO 8601，或 `start_at >= end_at` | "公示开始时间必须早于结束时间" |
| 400 | `INVALID_DECISION` | `decision` 不是 `approve`/`reject`，或 `reason` 超 2000 字 | 检查选择项 |
| 400 | `REASON_REQUIRED` | 驳回但理由为空 | "未获批必须填写原因" |
| 400 | `INVALID_LENGTH` | `proposed_level` 超过 100 字 | 缩短等级名称 |
| 403 | `FORBIDDEN` | 角色不符（学生/辅导员/学院审核员调学生处接口）、学生查他人结果、学生处读申请列表 | 隐藏无权限入口 |
| 403 | `CSRF_REQUIRED` | 非 GET 请求缺 `X-CSRF-Token` 或过期 | 重新登录 |
| 404 | `NOT_FOUND` | 项目或公示批次不存在 | 刷新列表 |
| 409 | `ALREADY_PUBLISHED` | 该项目批次已有"公示中/已确认"的公示 | "该批次已发布" |
| 409 | `BATCH_INCOMPLETE` | 批次内仍有未审完的申请 / 没有待公示记录 / 确认时未覆盖整批 / 状态在提交过程中变化 | "批次还有未完成审核，不能整批发布" |
| 409 | `OBJECTION_UNHANDLED` | `objection_handled` 不是 `true` | "请先确认异议已处理" |
| 409 | `PUBLICATION_OPEN` | 公示期还没结束就确认 | "公示期尚未结束" |
| 409 | `ALREADY_FINALIZED` | 该批次已确认过，重复提交；`current_status` 会给出当前状态 | "该批次已确认，不能重复提交" |
| 415 | `JSON_REQUIRED` | 没带 `Content-Type: application/json` | 检查请求头 |

`ALREADY_FINALIZED` 是唯一带 `current_status` 的本轮新错误，前端可用它做幂等提示。

## 九、数据迁移与兼容

- `Store.__init__` 里调用 `migrate_publication_results()`，**幂等**：

## 十二、边界与这一轮没做的事

- **不做线上异议提交**：异议按线下处理，学生处勾选 `objection_handled` 即代表处理完毕。系统只记录勾选结果，不存异议内容。
- **不做提前结束公示**：公示期只能等 `end_at` 到期，没有"提前关闭"接口。
- **不支持撤销已确认的批次**：确认后 `已获批/未获批` 是终态；要改只能线下走变更，不改数据。
- **不提供导出**：名单和结果都只出 JSON，导出 Excel 不在本轮范围。
- **学生处看不到申请明细和附件**：这是有意的权限隔离，不是缺陷；需要看原件请走辅导员/学院账号。
- **US07 / US08 未实现**：本文不涉及，不要在前端预留入口后声称已实现。
- 本轮未写任何自动化测试，测试由测试成员按实验一 Given/When/Then 补齐；本文所有示例均来自本机实测。
